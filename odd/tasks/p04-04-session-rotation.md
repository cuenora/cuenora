## Specs

- **S1:** User: “Comencemos con la tarea P04.04 del plan maestro”. Roadmap: “Implement session/refresh-token rotation and revocation.” Implement atomic refresh rotation and owning-session revocation using existing opaque credentials and persisted session families.
- **S2:** User answered “Sí” to: “recomiendo que reutilizar un refresh token ya consumido **revoque toda esa sesión**, sin afectar otras sesiones.” Preserve this approved replay response, including the stated tradeoff that legitimate retries/concurrent refresh can require login. Derive ownership from the presented refresh digest, never caller-supplied session/user IDs.
- **S3:** User: “No, mejor vamos a rotarlo con cada uso para que sea indefinido mientras usen la app y si no se usa por mas de 30 dias si se vencería, de todas formas no es una app que pueda mover el dinero, solo es para llevar el control, creo que en esta fase hasta implementar passkey por comodidad podemos dejarlo así”. Each successful refresh issues fresh opaque access and refresh secrets; successor refresh expires 30 days after rotation, without an absolute family-age cap. Refresh use, not unrelated app activity, renews this deadline. Expired or revoked credentials cannot rotate. Preserve the existing 15-minute access lifetime.
- **S4:** Preserve existing registration, login, liveness, identity/financial data and password admission behavior. Retain consumed refresh generations and persist only token digests. Rotation and explicit session revocation must serialize on the owning family, preserve other sessions, and commit all effects or none; replay rejection intentionally persists family revocation. Never log credentials. Use isolated synthetic PostgreSQL tests, generic failures and bounded HTTP input/work.
- **S5:** Synchronize OpenAPI, setup and identity/session documentation with the implemented public refresh boundary. Keep bearer middleware (P04.05), broad authorization work, logout/global revocation (P04.11), email and passkeys out of this implementation. Do not mark later roadmap tasks or Phase 04 complete. Record only observed verification; publication requires separate authorization.
